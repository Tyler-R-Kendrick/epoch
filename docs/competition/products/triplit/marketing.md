# Marketing

## Target Customers

- Frontend and fullstack developers building collaborative, realtime, offline-capable applications.
- TypeScript teams that want schemas, validation, and query types in the same development loop.
- Startups that want to move quickly without assembling separate database, cache, realtime, offline, and state-management layers.
- Mobile and web teams that want one local-first data model across frameworks.

## Positioning

Triplit positions itself as "the fullstack database": a database that syncs between server and browser in real time while also supplying schemas, client cache, relational queries, offline support, conflict resolution, and framework integrations.

## Customer Model

- Open-source and self-hostable core.
- Hosted/dashboard experience for teams that want managed operations.
- Adoption through `npm create triplit-app`, docs, demos, framework integrations, GitHub, Discord, and testimonials.
- Strong developer-marketing motion around replacing several app data layers with one tool.

## Captured Audiences

- Developers who want local-first benefits without designing a sync protocol.
- React and React Native teams looking for typed hooks and fast UI state.
- Builders who prefer TypeScript schemas over scattered SQL/config files.
- Teams that value self-hosting but still want a polished product surface.

## Missed Or Under-Captured Audiences

- Enterprises standardized on SQL, existing ORMs, database governance, and mature operational controls.
- Teams needing source-control-style branches, review, signatures, and artifact provenance.
- Buyers that prefer narrowly scoped infrastructure over adopting a fullstack database model.
- Applications with complex file/object versioning needs outside ordinary synced records.
