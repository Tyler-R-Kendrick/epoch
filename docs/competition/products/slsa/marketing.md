# Marketing

## Target Customers

- Software producers that need to improve supply-chain integrity without adopting every control at once.
- Artifact consumers and enterprises that need a common language for trust decisions.
- Ecosystems, package registries, build platforms, and CI providers that mediate trust between producers and consumers.

## Positioning

SLSA positions itself as a common, incrementally adoptable framework for supply-chain integrity. The pitch is that teams can talk about assurance with shared levels and tracks instead of scattered checklists.

## Customer Model

SLSA is an OpenSSF community specification rather than a commercial product. Value is captured by tool vendors, CI platforms, package ecosystems, and security programs that implement or certify SLSA-aligned workflows.

## Captures

- Security leaders who need a maturity model that can be communicated across engineering, compliance, and procurement.
- Infrastructure providers that can make provenance generation part of their platform.
- Open-source ecosystems that want trust language without making every project design a custom security program.

## Misses

- Developers looking for a concrete UI or repository workflow.
- Teams that want all requirements automated by one product.
- Organizations with legacy build systems where provenance generation and verification require deep process changes.

## Epoch Lessons

SLSA captures assurance framing. Epoch should use that framing while competing on concrete source-history creation, inspection, and preservation.
