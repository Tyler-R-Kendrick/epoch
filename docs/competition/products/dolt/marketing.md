# Marketing

## Target Customers

- Developers who understand Git and want the same collaboration model for database tables.
- Data teams that exchange CSVs, maintain scraped datasets, publish public data, or need reviewable vendor/customer data updates.
- Application teams that want branchable customer data, previewable changes, rollback, or auditable data provenance.
- Organizations that want hosted data collaboration but need a self-hosted option for private datasets.

## Positioning

Dolt's core message is "Git for Data." The product is positioned as the first version-controlled SQL database, a MySQL-compatible server, and a collaboration ecosystem around data remotes. DoltHub is positioned as a GitHub-like sharing and pull request experience for databases; DoltLab as private on-prem DoltHub; Hosted Dolt as managed production infrastructure.

## Customer Model

- Open source engine licensed through the public Dolt repository.
- Free public data hosting and community discovery through DoltHub.
- Hosted Dolt for managed database deployments.
- DoltLab for self-hosted/private collaboration.
- Enterprise-style capture through managed hosting, private deployments, support, and production operations.

## Captured Audiences

- Git-native developers who are frustrated by opaque database state.
- Data publishers who want contributors, diffs, provenance, and rollback.
- Teams that can adopt MySQL-compatible infrastructure or run Dolt beside existing systems.
- Technical buyers who value transparent architecture and open source.

## Missed Or Under-Captured Audiences

- Postgres-first teams that do not want to wait for Doltgres maturity.
- Non-technical spreadsheet users who need collaboration but do not want Git or database concepts.
- Teams with high-write OLTP workloads that prioritize mature MySQL operational behavior over versioning.
- Teams whose versioned assets include source, binary design files, policy events, generated outputs, and agent context in one repository.
