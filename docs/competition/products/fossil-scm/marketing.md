# Marketing

## Target Customers

- Developers and small teams that value self-hosting, reliability, and low operational burden.
- Projects that want code, documentation, tickets, and discussion stored together.
- SQLite-adjacent users who trust small, durable C tools and long-lived file formats.
- Teams that prefer conservative, append-only history semantics over rebase-heavy Git workflows.

## Positioning

Fossil positions itself as a coherent software configuration management system, not merely a VCS. It emphasizes high reliability, all-in-one project management, a built-in web interface, trivial installation, self-host friendliness, simple networking, autosync, and SQLite-backed durability.

## Customer Model

Fossil is free and open source under the 2-clause BSD license. It does not use a SaaS subscription model; value accrues through adoption of the tool and optional self-hosting.

## Captures

- Sovereignty-minded developers who do not want dependence on GitHub, GitLab, or Atlassian.
- Small projects that want a complete project website on minimal infrastructure.
- Offline and low-bandwidth workflows that benefit from efficient sync and local search.
- Users who value repository-integrated discussion and documentation.

## Misses

- Teams whose hiring, onboarding, and automation assume GitHub-compatible Git workflows.
- Large organizations that need vendor support, enterprise procurement, and a big integration marketplace.
- Developers who rely on rebase, Git LFS, git-annex, or GitHub-native collaboration conventions.
- Users expecting a polished modern SaaS interface.

## Epoch Lessons

- Epoch should borrow the "project context is repository data" message, but avoid Fossil's adoption trap by staying interoperable with Git and modern platform workflows.
