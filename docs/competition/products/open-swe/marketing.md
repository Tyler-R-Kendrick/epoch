# Marketing

## Target Customer

Open SWE targets engineering organizations that want internal coding agents but prefer open-source framework control over a closed SaaS agent. The buyer or champion is likely a platform engineer, AI engineering team, or developer-productivity group already comfortable with LangChain, GitHub Apps, cloud sandboxes, and workflow automation.

## Positioning

- Open SWE is positioned as an open-source asynchronous coding agent and, more recently, a framework for internal coding agents.
- It frames the category shift from autocomplete and IDE copilots toward long-running cloud agents that plan, code, test, self-review, and open PRs.
- The marketing highlights control: human plan review, interruptibility, double-texting, custom tools, custom prompts, model choices, and internal deployment.

## Customer Model

- The project is open source and repository-driven.
- LangChain benefits from organizations adopting LangGraph, Deep Agents, LangSmith, and related deployment/observability infrastructure.
- The hosted demo path asks users to connect GitHub and provide an Anthropic API key, while serious teams are expected to customize and operate the stack.

## Who They Capture

- Teams building internal agents instead of buying one proprietary workflow.
- LangChain-aligned developers who want a concrete agentic software-engineering reference app.
- Organizations that need Slack, Linear, GitHub, sandbox, and PR automation patterns they can inspect and change.

## Who They Miss

- Individual developers who want an immediate local coding assistant.
- Enterprises that want vendor-managed support and contractual assurances around security and compliance.
- Teams that need tool-agnostic signed provenance rather than framework-level run state.

## Epoch Opportunity

Epoch can treat Open SWE as a complementary runtime and provide the missing cross-tool evidence contract: signed plan state, user interrupts, code actions, tests, reviews, and PR linkage.
