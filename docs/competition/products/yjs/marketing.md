# Marketing

## Target Customers

- Developers building collaborative editors, whiteboards, design tools, notebooks, or multiplayer application state.
- Framework and product teams that need a proven CRDT substrate but want to own their app UX.
- Open-source projects that need broad editor and language integrations.
- Teams that want to avoid lock-in to one sync provider or backend topology.

## Positioning

Yjs positions itself as modular building blocks for collaborative applications. The main promise is high-performance automatic sync through shared types, plus a broad connection and persistence ecosystem.

## Customer Model

- Open-source framework adoption through npm packages, docs, demos, and community integrations.
- Commercial capture is indirect: companies build products and hosted collaboration platforms on top of Yjs rather than buying Yjs as a packaged SaaS.
- The ecosystem model depends on bindings, providers, ports, and community expertise.

## Captured Audiences

- Teams that need live collaboration quickly and want to start from proven editor integrations.
- JavaScript and TypeScript developers building browser-based multiplayer apps.
- Infrastructure teams that value network-agnostic sync and custom providers.
- Products where awareness and cursor presence are core to the user experience.

## Missed Or Under-Captured Audiences

- Buyers looking for an end-user product, hosted admin console, or enterprise support contract.
- Teams that need source-control semantics, signed commits, review workflows, and durable audit trails.
- Non-editor workloads where shared types are useful but not enough to model repository evolution.
- Teams without the appetite to integrate and operate a collaboration backend.
