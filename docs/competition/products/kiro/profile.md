# Kiro

Kiro is an AWS-backed agentic development environment spanning IDE, CLI, and web surfaces. It is built around specs, steering, hooks, subagents, MCP, and credit-metered agent execution. Its core pitch is moving from prototype-style prompting toward structured requirements, design, tasks, and implementation.

## Competitive Relevance

- Kiro competes with Cursor, Windsurf, Replit Agent, Claude Code, Codex, and Junie by making specification-driven development the center of the agent workflow.
- Specs turn a natural-language idea into requirements, architecture, and task plans before implementation.
- Steering files preserve workspace, global, and team conventions in markdown, while hooks automate file-save or workflow-triggered tasks.
- Kiro's pricing and enterprise story target both individual developers and governed teams that want SSO, usage analytics, organizational dashboards, and security controls.

## Epoch Implications

- Kiro's spec artifacts are close to the durable planning layer Epoch should preserve around agent-authored changes.
- Hooks and subagents create background execution paths that need clear provenance, especially when docs, tests, or generated code change without a direct human edit.
- Epoch can differentiate by signing the relationship among intent, spec, task execution, command evidence, and final commits.

## Unknowns To Track

- Kiro's credit model, model routing, and web/CLI/IDE feature parity are still evolving.
- Enterprise adoption depends on how safely Kiro scopes AWS and local credentials when agents can execute background work.
