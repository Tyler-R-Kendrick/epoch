# Grafeas Marketing

## Target Customer

Grafeas targets platform security teams, cloud platform engineers, artifact registry owners, Kubernetes operators, and organizations that need centralized metadata about software artifacts. The audience is technical and infrastructure-heavy.

## Positioning

Grafeas is positioned as an open artifact metadata API for supply-chain security. The managed Google Cloud framing turns similar concepts into vulnerability management, SBOM, provenance, and policy workflows around Artifact Registry and container deployment.

## Customer Model

- Open-source API and server model.
- Kritis provides an open policy-enforcement companion for Kubernetes admission control.
- Commercial pull is stronger through cloud-managed artifact analysis, registry, and security products than through Grafeas alone.

## Who They Capture

- Teams that need a metadata backbone across scanners, build systems, and deployment policy.
- Cloud-native organizations with Kubernetes and container registry governance requirements.
- Security teams that prefer centralized artifact facts over local build logs.

## Who They Do Not Capture

- Developers seeking a source-control replacement or local collaboration model.
- Small teams without enough artifact volume to justify a metadata API.
- Buyers who want source history, review intent, and merge causality represented before artifacts are built.

## Differentiation Notes

Grafeas differentiates by making artifact facts queryable and reusable across tools. Epoch can differentiate by producing higher-quality source and version facts that feed the metadata layer with stronger causal context.
