# Grafeas Gossip

## Positive Signals

- The Grafeas model is respected for making supply-chain metadata interoperable instead of trapped in one scanner.
- Google Cloud Artifact Analysis keeps related concepts visible to cloud buyers through a managed registry and vulnerability workflow.
- The metadata categories are broad enough to support vulnerability response, provenance, deployment history, and policy.

## Critical Signals

- Standalone Grafeas can feel like infrastructure plumbing rather than a product with an obvious daily user experience.
- Kritis and open-source Grafeas public activity has appeared quieter than newer SBOM, SLSA, and scanner ecosystems.
- Teams still need to connect producers, storage, querying, policy, and dashboards to get an end-to-end workflow.

## Bug And UX Friction Themes

- Metadata gaps are common when one scanner, builder, or deployment system does not emit the expected occurrence type.
- Policy decisions can be difficult to explain if artifact metadata is incomplete or stale.
- Users may encounter the model through managed cloud docs, which can blur the line between open Grafeas and Google-specific product behavior.

## Epoch Takeaways

- Epoch should provide a clean metadata export story but avoid becoming only a passive evidence database.
- The stronger product opportunity is connecting artifact metadata back to signed repository history, named actors, and reviewable version materialization.
