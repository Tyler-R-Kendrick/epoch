# Marketing

## Target Customer

E2B markets to AI product teams building coding agents, data-analysis agents, tool-using agents, and code-interpreter workflows that need safe execution without building sandbox infrastructure in-house.

## Positioning

- Secure cloud sandboxes for AI agents.
- Run code, shell commands, templates, and tools in isolated Linux environments.
- Usage-based platform with a free Hobby tier, paid Pro tier, and Enterprise custom limits.
- Docker MCP partnership positions E2B as a trusted tool-execution layer, not only a compute sandbox.

## Customer Model

E2B captures builders whose agents need executable environments at product scale. The model combines plan tiers with per-second usage, higher session lengths, configurable resources, and concurrency expansion for production workloads.

## Who They Capture

- AI startups adding code execution or generated-code validation.
- Agent framework and app developers who want a common sandbox backend.
- Teams that want MCP tools available inside an isolated environment.
- Product teams that can tolerate usage-based unit economics in exchange for speed.

## Who They Do Not Capture

- Teams that primarily need human developer environments.
- Buyers who need predictable per-seat CDE budgets rather than runtime billing.
- Organizations that require first-party signed repository history instead of runtime isolation.
- Users who need full desktop GUI automation across multiple operating systems.

## Epoch Opportunity

E2B makes sandbox execution easy to embed. Epoch should make the outputs and decisions from that execution portable, signed, reviewable, and tied to the repository timeline.
