# Marketing

## Target Customers

- Developers who want a fast native editor with built-in AI and real-time collaboration.
- Teams adopting agentic workflows where humans review, steer, and revise agent work in the same workspace.
- Organizations willing to standardize on Zed for performance, open-source auditability, and centralized AI controls.

## Positioning

Zed positions DeltaDB as the next step after a high-performance AI-native editor: operation-level version control that lets humans and agents share a live, consistent, code-linked history. The message is not "replace Git today"; it is "Git snapshots are not enough for continuous collaboration."

## Customer Model

Zed is an open-source editor with free personal use, Pro AI usage, Business controls, and a stated plan to open-source DeltaDB while offering an optional paid service.

## Captures

- AI-heavy teams that want editor-native orchestration, review, and context capture.
- Distributed teams that already value pairing, mentoring, shared notes, and ambient awareness.
- Developers frustrated by stale permalinks, lost Slack context, and commit history that explains what changed but not why.
- Security reviewers who prefer open-source clients and configurable AI data policies over closed editor forks.

## Misses

- Teams that want repository history to remain independent of any one editor.
- Regulated organizations that need self-hosting, formal audit controls, and a published storage/security model before adoption.
- Git CLI and forge-first teams that treat editor state as transient.
- Users who see AI-centric editor positioning as distracting from core editor or VCS fundamentals.

## Epoch Lessons

- Epoch should lead with portable trust primitives: signed events, local verification, deterministic policy, and inspectable storage.
- The marketing must explain why operation-level history is useful after noise is removed, not merely that more history exists.
- Epoch should integrate with editors without becoming editor-dependent.
