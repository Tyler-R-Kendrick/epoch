# Anything Create Design

## Look And Feel

Anything uses a playful, creation-focused app-builder design: prompt-to-app language, live builder screenshots, project navigation, publish controls, version history shortcuts, settings for assets/secrets/auth/social metadata, and pricing tables centered on credits and agent capability.

## Differentiators

- The product explains project architecture in user terms: pages, components, functions, databases, user accounts, and assets.
- Multiple AI modes make agent intensity visible: Auto, Thinking, Discussion, and Max.
- Pricing markets automated testing, connection verification, visual QA, and plain-language error explanation as paid capability.
- Version history is surfaced as a builder affordance, including a documented keyboard shortcut.

## What Works Well

- The docs make the builder mental model more concrete than many vibe-coding tools.
- Discussion Mode and credit-optimization guidance acknowledge that blind prompting wastes money.
- Publish docs call out test-to-live database sync and failed publish badges, which is useful operational detail for non-technical users.
- Code export reduces lock-in for paid users.

## Where UX Breaks Down

- Credit accounting is central to the experience and can turn exploration, repair, and published AI features into cost anxiety.
- Rebrand and migration complaints suggest product identity and continuity can become trust problems.
- If Max, visual QA, or autonomous testing fail, users may feel the most expensive plan did not deliver the promised reliability.
- Broad web/mobile/full-stack claims can overrun what a non-technical user can safely verify before launch.

## Epoch Design Takeaway

Epoch should borrow the explicit project-architecture language and testing-as-proof ambition, but keep evidence separate from marketing claims. A generated test is only valuable when the user can inspect what it covered.
