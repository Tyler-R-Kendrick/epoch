# Tempo Labs Design

## Look And Feel

Tempo's design posture is product-design-first: a visual React editor, Figma import language, component manipulation, and planning-oriented generation. The market material and community descriptions emphasize a design-tool feel rather than a terminal or forge workflow.

## Differentiators

- Visual editing is treated as the primary interface for React work, not a secondary preview.
- Planning before generation differentiates Tempo from prompt-only builders that immediately rewrite code.
- Figma and GitHub are explicit workflow anchors, which makes the product feel collaborative for designer/developer teams.
- The UI promise is quality and maintainability, not only speed.

## What Works Well

- Tempo speaks to teams that already have design assets and want usable React output.
- Visual editing can reduce prompt-credit waste for layout tweaks if it works reliably.
- GitHub sync gives developers a familiar escape hatch and review surface.
- Planning-first workflows help users reason about navigation and page structure before code changes.

## Where UX Breaks Down

- Public complaints mention import/export reliability, GitHub-only access friction, auth problems, and preview/deploy failures.
- Figma import raises expectations that are hard to satisfy for complex existing designs.
- React focus is a strength for UI fidelity but a weakness for teams expecting a full business-app backend.
- A slower planning step may frustrate users who only want a quick prototype.

## Epoch Design Takeaway

Epoch should watch Tempo as evidence that future repository workflows will need to capture design intent, visual edits, generated code, and deployment proof in a single history model.
