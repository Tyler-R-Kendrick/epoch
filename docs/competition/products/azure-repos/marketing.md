# Marketing

## Target Customers

- Microsoft-centered engineering organizations already using Azure, Visual Studio, Entra ID, or GitHub Enterprise.
- Enterprises that want private Git repos, Boards, Pipelines, Test Plans, Artifacts, and governance under one vendor.
- Teams that need centralized permissions, auditability, and policy enforcement more than local-first autonomy.

## Positioning

Azure DevOps is positioned as a suite of modern development services to plan, collaborate, and ship faster. Azure Repos is one service in that suite, not the headline product.

## Customer Model

- Azure DevOps Basic includes Azure Repos and is free for the first five users, then priced per Basic user.
- Visual Studio subscribers and eligible GitHub Enterprise users can receive Azure DevOps access through existing Microsoft relationships.
- Additional monetization comes from Pipelines capacity, Test Plans, Artifacts storage, and security add-ons.

## Captures

- Enterprises that buy through Microsoft and prefer centralized governance.
- Teams that want work-item traceability and CI/CD enforcement built into PR completion.
- Organizations where Azure Boards and Pipelines are already the planning and delivery source of truth.

## Misses

- Open source communities that prefer GitHub's network effects or self-governed forges.
- Teams that need local-first repository identity, offline review, peer-to-peer sync, or verifiable history outside a Microsoft tenant.
- Small teams that find Azure DevOps administration heavier than their collaboration problem.
