# Marketing

## Target Customers

- Developers and teams who want distributed version control without Git's perceived complexity.
- Projects that value reliable local operations, simple commands, and conservative history-sharing behavior.
- Existing Mercurial users and organizations with legacy Mercurial infrastructure.

## Positioning

Mercurial positions itself around working easier and faster: a free distributed source control tool that handles projects of any size with an easy, intuitive interface.

## Customer Model

- Open source project and ecosystem tooling rather than a SaaS subscription business.
- Commercial value is mostly indirect through hosting, migration, consulting, and support around organizations that still run Mercurial.

## Captures

- Users who prefer clean VCS ergonomics and explicit shared-history safety.
- Teams that need local distributed history but do not want a large hosted forge to define the workflow.

## Misses

- New mainstream teams that default to Git because hosting, CI, IDE integration, and hiring expectations are Git-first.
- Enterprises that want bundled governance, identity, review, and audit UI from a vendor.
- Product-led buyers looking for a polished collaboration surface rather than a command-line VCS.
