# Marketing

## Target Customers

- Developers already on Bluesky / ATProto who want code hosting with the same
  identity.
- Open source maintainers who want self-hostable Git (knots) without leaving a
  social network.
- Teams interested in stacked PRs, lightweight CI (spindles), and forge
  alternatives to GitHub.
- Infrastructure enthusiasts willing to run knots/spindles or consume managed
  free tiers.

## Positioning

"Tightly-knit social coding" / "next-generation social coding platform" built on
AT Protocol: ownership of code and communities, self-governance, and making
coding social and fun again. Contrasts itself with centralized forges and with
pure P2P models by using AT identity plus self-hostable Git hosts.

## Customer Model

Open source core with managed hosting and CI free to use on tangled.org.
Monetization path is not the primary public message; adoption is ecosystem and
community driven (Discord/IRC, Bluesky, newsletter).

## Captures

- ATProto-native users and multi-app "atmosphere" identity.
- Self-hosters who still want a polished multi-tenant AppView.
- Social discovery (follow, star, timeline) adjacent to code.

## Misses

- Enterprises needing private-by-default social metadata and SSO-heavy control
  planes (AT public-record constraints).
- Users who refuse Git as the code substrate.
- Teams that need full GitHub Actions marketplace depth today.

## Epoch Counter-Positioning

- Epoch: signed event-log DVCS with optional federated social, not "Git + AT
  metadata only."
- Epoch: private Community off-switch and Platform deploy/ops as first-class.
- Epoch: Git via compatibility proxy for generic Git interop/migration; Core
  stays authoritative. No product bridge to competing forges.
