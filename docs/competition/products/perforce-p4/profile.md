# Perforce P4

Perforce P4, formerly Helix Core, is a centralized version-control platform for large binary assets, global teams, and enterprise permissions. It competes with Epoch where versioned history must cover source code, design assets, build artifacts, game files, and regulated IP at scale.

## Competitive Relevance

- P4 owns a strong position in game development, VFX, semiconductor, automotive, and other asset-heavy engineering domains.
- Its differentiators are scale, file locking, streams, proxy and edge servers, granular permissions, audit trails, visual clients, and integrations with creative tooling.
- Perforce markets P4 as a replacement for Git when file size, binary assets, global distribution, and IP control matter more than decentralized workflows.
- P4 Cloud makes the historically self-managed platform more accessible to smaller teams, while enterprise plans keep the sales-led model.
- The product family includes visual clients, code review, DAM, planning, and Git connector surfaces.

## Epoch Implications

- Epoch should not treat Git-style source workflows as the whole market; large binary assets and creative workflows are major competitive requirements.
- File locking and visual asset history remain important when merge is not viable.
- Enterprise buyers expect permissions, audit, topology, backup, and support details to be concrete.
- Epoch can differentiate with local-first signed event history, open TypeScript/WASM surfaces, and agent-friendly repository semantics, but it must acknowledge binary and asset-scale needs.

## Unknowns To Track

- How quickly P4 Cloud changes adoption among small and mid-sized teams that previously avoided Perforce operations.
- Whether P4 One and newer visual tools reduce the historic UX friction associated with Perforce.
- How teams balance Git connector workflows with P4-native creative and binary asset workflows.
