# Ona Marketing

## Target Customer

- Engineering leaders who believe local development environments block agent adoption.
- Platform and DevOps teams responsible for standardizing developer workspaces.
- Security-conscious organizations that need agents to run in controlled infrastructure.
- Teams already using GitHub, GitLab, Linear, Jira, Notion, Cursor, Claude Code, or repository instruction files.

## Positioning

Ona positions itself as the platform for background agents, not merely as a hosted IDE. The core claim is that AI software engineers need standardized, reproducible, secure environments to operate at scale. The product message reframes Gitpod's original "ready-to-code" promise as an agent operations layer.

## Customer Model

- Ona Cloud for fast starts.
- VPC or cloud-runner deployment for teams that need control over source code, secrets, and infrastructure.
- Organization-level billing and usage credits.
- Enterprise controls around SSO, OIDC, SCIM, policies, guardrails, audit logs, and runner infrastructure.

## Captured Audiences

- Teams adopting background agents but unwilling to run them on uncontrolled laptops.
- Companies with existing Dev Container or cloud-dev-environment investments.
- Platform teams that want one repeatable environment model across human and AI work.

## Missed Audiences

- Individual open-source contributors who mainly want a free, simple browser workspace.
- Teams that want vendor-neutral signed provenance more than another managed agent platform.
- Developers who prefer a local-first workflow and see cloud environments as latency, cost, or lock-in.
