# Design

## Look And Feel

Rork uses a sparse, founder-oriented landing and builder entry surface: a direct prompt box, mobile platform selector, file upload affordance, App Store outcome copy, and documentation organized around app ideas, testing, publishing, monetization, and marketing.

## Open Design Artifacts

- The homepage shows the main prompt-first app creation surface and mobile-focused upload limits.
- Docs expose the information architecture for the product workflow: getting started, testing, Rork Max, monetization, publishing, backend, integrations, GitHub sync, and marketing.
- The product's design artifact is less a public token system and more a mobile-launch workflow map.

## Differentiators

- Rork is explicitly mobile-first; the goal is not a generic web app preview but a native mobile app users can ship.
- The docs pair creation with founder education, including app validation, paywalls, free trials, store publishing, and influencer/organic marketing.
- Removing native tooling setup is a strong UX differentiator for non-mobile specialists.

## What Works Well

- The app-store and monetization framing creates a concrete outcome for builders.
- Plain-language docs reduce the intimidation of mobile build pipelines and store requirements.
- GitHub sync gives developers a way to inspect or extend work after the AI-generated draft.

## Where It Breaks Down

- Mobile apps need device-specific QA, accessibility, store compliance, privacy disclosures, and release-signing discipline that a simple chat surface can make look easier than it is.
- Pricing and Rork Max boundaries are not as transparent in public crawlable pages as the core creation pitch.
- Founder-growth content is useful, but it can blur the line between app engineering proof and go-to-market advice.
