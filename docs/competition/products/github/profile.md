# GitHub

GitHub is the incumbent developer collaboration platform rather than a pure DVCS. For Epoch, it is the baseline users will compare against for repositories, issues, pull requests, code review, CI status, and social proof.

## Competitive Relevance

- GitHub owns the default mental model for "where code lives" and captures network effects around identity, hosting, issues, CI, releases, and package distribution.
- Its product surface is mature but broad; the same breadth that makes it sticky makes it hard for non-expert users to understand basic flows like cloning, downloading, branching, and merging.
- Epoch should treat GitHub compatibility as a migration and trust bridge, while differentiating on signed append-only history, offline-first collaboration, and conflict-safe entity merging.

## Epoch Implications

- Do not compete first on "another place to host repos"; compete on workflows GitHub makes difficult: offline collaboration, signed intent history, deterministic replay, local-first review, and low-friction sync.
- If Epoch develops UI, it needs a clearer beginner path than GitHub's repository chrome while keeping expert density for CLI users.
