# Marketing

## Target Customer

GitHub markets Copilot coding agent to developers and teams already using GitHub for issues, pull requests, Actions, and code review. The strongest fit is organizations that want AI delegation inside existing repository governance instead of a separate agent workspace.

## Positioning

- "Assign work to Copilot" positions the product as a teammate-like worker rather than autocomplete.
- GitHub emphasizes PR workflow integration, ephemeral environments, tests, code review, secret scanning, and existing repo controls.
- The pricing story bundles agent usage into Copilot plans while progressively exposing more granular usage accounting for model-heavy workflows.

## Customer Model

- Individual developers can use Copilot plans for chat, agent mode, code review, CLI, and coding agent usage.
- Business and Enterprise plans sell higher limits, policy controls, organization management, and enterprise surfaces.
- Usage-sensitive agent work is increasingly metered through premium requests or AI-credit style billing rather than pure seat value.

## Who They Capture

- GitHub-first engineering teams that do not want another code host, agent dashboard, or review process.
- Managers who want AI work to show up as pull requests in the same queue as human work.
- Enterprises that already trust GitHub policy, Actions, secret scanning, and identity controls.

## Who They Miss

- Teams that need forge-neutral, self-hosted, offline, or content-addressed history independent of GitHub.
- Teams that want a signed ledger of every agent step instead of PR-centered audit fragments.
- Users who dislike AI affordances appearing broadly across GitHub and VS Code surfaces.
