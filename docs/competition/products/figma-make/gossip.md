# Gossip

## Positive Signals

- Designers respond to Make because it keeps prompting, editing, and high-fidelity exploration inside the design environment they already use.
- Public coverage treats Figma's GitHub and local-code direction as a serious attempt to connect design work with production code.
- Make kits and connectors are viewed as stronger context controls than generic screenshot-to-code tools.

## Negative Signals

- Figma forum feedback complains that AI credit limits make sustained Make usage hard to adopt as a core workflow.
- Visual QA commentary around AI app builders warns that generated prototypes can contain many visual and interaction defects even when they look impressive at first glance.
- Some market coverage frames Figma Make's production-code ambition as potentially disruptive but still dependent on governance and engineering review.

## Bug And Trust Themes

- Credit anxiety can discourage experimentation, which is the very behavior Figma Make is designed to support.
- Design fidelity is not the same as production correctness.
- Connector-backed context needs clear audit trails because the generated result may depend on private docs, tasks, PRs, or issue data.

## Epoch Takeaway

Figma Make pulls product intent into the design canvas. Epoch should capture frame, connector, design-system, model, code, and publish evidence so design-native generation can become auditable engineering input instead of an attractive but lossy prototype.
