# Marketing

## Target Customer

Daytona markets to AI product builders, platform teams, and agent infrastructure teams that need secure, elastic sandboxes for AI-generated code, data analysis, GUI automation, and long-running agent workflows.

## Positioning

- Secure infrastructure for running AI-generated code.
- Instant sandboxes with state, snapshots, resource controls, and computer-use APIs.
- Pay-as-you-go compute with free credits and startup/enterprise programs.
- Full computer environments rather than narrow code snippets.

## Customer Model

Daytona captures teams whose product margin depends on giving agents execution environments without building sandbox infrastructure themselves. Pricing is usage-based, with enterprise and startup motions for larger workloads.

## Who They Capture

- AI app teams building code execution, data analysis, browser/desktop automation, or coding-agent products.
- Builders who need API-first sandbox creation and lifecycle control.
- Teams that value stateful snapshots and observable per-sandbox cost.
- Enterprises that want on-premise setup or volume discounts.

## Who They Do Not Capture

- Teams that only need local development environments for humans.
- Buyers who require a fully mature Windows or macOS Computer Use product today.
- Organizations that want fixed per-seat budgeting instead of usage-based runtime economics.
- Users whose main concern is signed repository history rather than sandbox execution.

## Epoch Opportunity

Daytona makes agent execution easy. Epoch should make agent execution accountable by linking each sandbox action to durable provenance, approvals, test evidence, and resulting repository state.
