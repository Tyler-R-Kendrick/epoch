# Marketing

## Target Customers

- JavaScript, Python, Ruby, and polyglot teams exposed to open-source package risk.
- Developer-first security teams that want PR-native supply-chain checks.
- Organizations worried about malware, typosquats, package takeovers, install scripts, and AI-agent dependency changes.

## Positioning

Socket positions itself as proactive supply-chain security. The message contrasts behavior and reachability analysis with traditional vulnerability scanners that alert after advisories are known and often create noisy backlogs.

## Customer Model

Socket uses a developer-seat SaaS model with free, team, business, and enterprise tiers. Higher tiers add larger scan volumes, reachability, Slack alerts, compliance integrations, SBOM import/export, SSO, webhook automation, and enterprise-grade reachability.

## Captures

- Teams that want security checks directly inside GitHub pull requests.
- Buyers willing to pay to reduce false positives and detect malicious package behavior earlier.
- Open-source maintainers and developer communities attracted by package health scores and free public-package analysis.

## Misses

- Organizations requiring fully self-hosted, open-source-only security infrastructure.
- Teams that need source-history signatures and content-addressed version materialization as the primary product.
- Buyers uncomfortable with proprietary scoring or SaaS dependency telemetry.

## Epoch Lessons

Socket captures the package-intake moment. Epoch should make that same moment durable in repository history: what changed, why it was trusted, who accepted the risk, and which materialized versions inherited it.
