# CodeSandbox Marketing

## Target Customer

- Frontend developers and teams sharing live, runnable examples.
- AI product builders who need secure code execution and sandbox lifecycle APIs.
- Education, interview, design-system, and documentation teams embedding runnable code.
- CI, eval, and agent teams that need parallel isolated environments.

## Positioning

CodeSandbox positions itself as instant development infrastructure. The newer SDK message is explicitly agent-facing: create isolated sandboxes, run code securely, fork or hibernate VMs, resume context, and use sandboxes for code generation, evals, and CI.

## Customer Model

- Account-based usage for the SDK, with API keys required.
- Individual and team usage around browser sandboxes, private repos, collaboration, and integrations.
- Enterprise and platform usage where sandboxing becomes embedded infrastructure inside another product.
- Strategic tie-in with Together AI for code interpretation and agent infrastructure.

## Captured Audiences

- Teams that want a fast web-native way to share runnable code and previews.
- AI app builders who do not want to build isolated execution infrastructure themselves.
- Design-system and documentation teams that benefit from embedded live examples.

## Missed Audiences

- Regulated enterprises that need full self-hosted provenance and audit chains around every agent action.
- Backend-heavy teams that need arbitrary native dependencies, complex local networks, or long-lived machines.
- Developers who see browser IDEs as weaker than their local editor and terminal setup.
