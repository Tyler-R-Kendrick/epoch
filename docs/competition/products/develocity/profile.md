# Develocity

Develocity is Gradle's developer-productivity platform for build and test observability, Build Scan reports, Universal Cache, Predictive Test Selection, Test Distribution, flaky-test detection, failure analytics, performance insights, and emerging provenance/governance features. It competes with Epoch around evidence-rich build history, source-to-build traceability, and organizational controls for fast, trustworthy software delivery.

## Competitive Relevance

- Develocity records detailed build and test data across Gradle, Maven, and sbt, then presents it through Build Scan links, analytics, failure dashboards, and performance views.
- Universal Cache and remote build cache nodes reuse deterministic build outputs across developers and CI.
- Predictive Test Selection uses Build Scan data to run likely-relevant tests and report which tests were selected or skipped.
- The marketing has shifted toward AI-driven delivery pressure: more generated code increases the need for faster CI, observability, and governance.

## Epoch Implications

- Epoch should expect buyers to compare signed source history against Develocity-style operational evidence: build scans, cache origin, dependency comparisons, test selection explanations, and failure analytics.
- Epoch can differentiate by making source identity, materialized tree identity, and build/test evidence tamper-evident rather than simply observable.
- Develocity's "Attest" positioning means build-observability vendors are moving closer to provenance and policy territory.

## Unknowns To Track

- Develocity packaging, pricing, and "Provenance Governor" details are not fully self-serve in the reviewed public pages.
- Current docs reflect active release churn in plugin APIs, predictive selection, cache edge behavior, and Gradle Enterprise to Develocity migration.
