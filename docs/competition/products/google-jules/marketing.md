# Google Jules Marketing

## Target Customer

Jules targets developers and maintainers who want routine coding chores handled asynchronously: bug fixes, version bumps, tests, documentation, and feature work. The homepage also appeals to builders who want more time for the code they enjoy while an agent handles background tasks.

## Positioning

- Jules is an autonomous coding agent, not an autocomplete assistant.
- The core promise is async GitHub work: describe the task, let Jules work in a Cloud VM, review a diff, and publish.
- The product is packaged around task throughput: free evaluation, Pro daily use, and Ultra high-concurrency agent-heavy work.

## Customer Model

- Free Jules offers limited daily and concurrent tasks.
- Paid access is included through Google AI Pro and Google AI Ultra plans.
- Current paid plan availability favors individual Google accounts, while Google says business upgrade paths are in progress.

## Who It Captures

- Maintainers with repetitive GitHub issues and chores.
- Individual developers already subscribed to Google AI plans.
- Teams experimenting with async agent queues before formal enterprise procurement.

## Who It Misses

- Enterprises that need immediate Workspace-native purchase, SSO, audit, and retention controls.
- Developers who want an IDE-local pair programmer rather than a background GitHub worker.
- Teams that need vendor-neutral provenance and long-lived evidence for agent-created branches.

## Epoch Opportunity

Jules makes async agent work approachable. Epoch should make the resulting project history trustworthy by capturing plans, diffs, checks, and approvals as signed records independent of the Google task UI.
