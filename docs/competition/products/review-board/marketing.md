# Marketing

## Target Customers

- Engineering organizations that need a dedicated review platform rather than only pull requests inside a forge.
- Teams with mixed SCM environments, including Git, Mercurial, Perforce, SVN, and legacy systems.
- Companies that review code, screenshots, documents, and design artifacts together.
- Organizations that want self-hosted review software or a hosted RBCommons option.

## Positioning

Review Board positions itself as a flexible, mature code review system for many repository types and review artifacts. The messaging is less about social coding and more about review discipline, visibility, and integration with existing development infrastructure.

## Customer Model

The project offers self-hosted open-source Review Board and hosted RBCommons. Commercial capture comes from hosted service, support, and the value of keeping a common review process across heterogeneous infrastructure.

## Captures

- Enterprises with legacy SCM or mixed toolchains.
- Teams that need structured review requests, issue tracking, and attachment review.
- Buyers who prefer a dedicated review tool over a full DevSecOps suite.

## Misses

- GitHub-native startups that want review, CI, projects, packages, and social discovery in one place.
- Teams that expect a highly modern consumer-grade UI.
- Organizations that want repository storage, hosting, and review in one single product.

## Epoch Lessons

Epoch should treat review as evidence that may live outside the repository host. The market still values portable, SCM-neutral review records when infrastructure is mixed.
