# Roo Code Marketing

## Target Customer

Roo Code targeted developers and teams who wanted a powerful, customizable AI coding agent inside VS Code, plus cloud or routing options for more autonomous work. The docs explicitly framed the product as for users who were willing to trade tokens for quality through frontier models with filesystem access, terminal control, and multi-step workflows.

## Positioning

Roo Code positioned itself as an "AI Software Engineering Team" rather than a simple copilot. The marketing emphasized power, customization, local control in VS Code, autonomous cloud work, orchestrator modes, codebase indexing, checkpoints, todo lists, and MCP extensibility.

## Customer Model

- Extension-led adoption for VS Code users.
- Paid cloud/router economics before shutdown.
- Community support, Discord, Reddit, YouTube tutorials, GitHub issues, and feature requests.
- Marketplace discovery for MCPs and modes.
- As of current docs, all products were scheduled to shut down on May 15, 2026, with unused-balance refunds.

## Who It Captured

- Power users who wanted to customize agent behavior deeply.
- VS Code users who preferred extension-native workflows over new IDEs.
- Teams experimenting with MCP tools and role-specific modes.
- Users comfortable paying higher token costs for stronger models and more agent autonomy.

## Who It Did Not Capture

- Users who wanted predictable long-term product continuity.
- Beginners who needed a simple, opinionated assistant.
- Organizations requiring a mature enterprise trust and audit story around third-party mode or MCP installation.
- Users who wanted low-cost, low-token workflows.

## Marketing Strengths and Weaknesses

Roo Code's strongest message was honest about power and cost: it did not pretend autonomous file and terminal access would be cheap. The weakness is that the proposition depended on product availability and a complex configuration ecosystem. Once shutdown entered the story, continuity became the dominant competitive concern.
