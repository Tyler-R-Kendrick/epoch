# Amazon Q Developer Marketing

## Target Customer

AWS markets Q Developer to individual developers, AWS builders, enterprise cloud teams, platform operators, and organizations modernizing Java applications or standardizing development workflows around AWS identity and governance.

## Positioning

- "Build, extend, and operate AWS applications" is the broad product frame.
- The coding story spans completions, chat, agentic development, code review, security scanning, and transformation.
- AWS emphasizes that Q is available in developer tools and AWS surfaces rather than being a standalone coding-only product.

## Customer Model

- Q Developer has a perpetual free tier with monthly usage limits.
- Pro adds higher usage, administration, and organization-oriented controls.
- Java transformation is metered by lines of code, with free and Pro allowances and pay-as-you-go overages.

## Who It Captures

- AWS-centered engineering organizations that want one vendor for cloud, identity, support, and coding assistance.
- Teams modernizing Java systems where automatic upgrade diffs are easier to fund than generic chat assistance.
- GitHub organizations willing to try free AI code review and issue-to-PR workflows before deeper AWS setup.

## Who It Misses

- Teams avoiding AWS lock-in or wanting vendor-neutral local history.
- Organizations that need fully self-hosted or offline coding-agent infrastructure.
- Developers who want a cohesive agent workspace rather than AWS, IDE, CLI, and GitHub surfaces stitched together.

## Epoch Opportunity

Epoch should treat Q Developer as proof that agent work is entering governed enterprise channels. The gap is durable change memory: signed plans, review decisions, transformation summaries, and provenance that survive outside AWS-owned surfaces.
