# Amazon Q Developer Gossip

## What People Like

- AWS customers like that Q is already available where they work: IDEs, CLI, console, documentation, chat integrations, and GitHub.
- The Java transformation workflow is easy to explain to managers because it maps to a concrete modernization backlog.
- GitHub code review and issue-to-PR automation lower adoption friction for teams that do not want to change editors immediately.

## Repeated Complaints

- Developers report pressure from management to replace normal coding judgment with Q-authored user-story implementation.
- Some users complain that context and memory in the IDE extension are not strong enough for nontrivial existing codebases.
- Usage limits and line-of-code transformation billing require operator attention, especially when modernization jobs are large.

## Bugs And Friction

- The July 2025 VS Code extension incident created a lasting trust problem around extension supply-chain review and prompt-injection safety.
- The product surface is wide enough that teams can struggle to understand which Q capability, identity mode, or quota applies to a task.
- GitHub preview behavior still needs careful evaluation before teams rely on it for regulated development workflows.

## Epoch Takeaway

Q Developer's friction is exactly where Epoch can be useful: independent signed records for agent input, generated code, review comments, accepted fixes, and transformation provenance.
