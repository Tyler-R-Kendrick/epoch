# Gossip

## What People Say

RhodeCode has a quieter public reputation than the default forges. Public materials read like an enterprise product built for source-code administrators, while community material emphasizes open-source availability and long-running multi-VCS support.

## Design And UX Complaints

- The public docs show a traditional admin-navigation model, which can feel heavy compared with GitHub-style onboarding.
- Review queues are split between per-user notifications and per-repository pull request views, which is clear but less unified than newer cross-repo dashboards.
- Sparse independent community discussion makes it harder for prospects to build confidence from public social proof.

## Feature Complaints

- AI code review is explicitly limited in the current docs: it can run once per pull request, so iterative automated review loops are not yet first-class.
- Enterprise breadth across Git, Mercurial, and SVN is valuable, but it can keep the feature set anchored to common-denominator SCM operations.
- Teams that want modern PR social workflows, package ecosystems, CI marketplaces, and large extension networks may find RhodeCode narrower than GitHub or GitLab.

## Product Risk For Epoch

RhodeCode is a reminder that conservative buyers may pay for governance, migration safety, and support even when the UX is less exciting. Epoch should not assume a better history model wins without an enterprise operating model.
