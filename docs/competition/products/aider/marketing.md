# Marketing

## Target Customer

Aider targets experienced developers who live in terminals, understand Git, and want an AI pair programmer that works with their existing editor and repository instead of requiring a new IDE or hosted workspace.

## Positioning

- Aider positions itself as "AI pair programming in your terminal."
- The marketing emphasizes open source, cloud and local model support, a repo map for large codebases, Git auto-commits, broad language support, IDE comment workflows, voice-to-code, screenshots/web pages, and lint/test repair loops.
- The public metrics around GitHub stars, installs, and token volume act as social proof for serious developer adoption.

## Customer Model

- Aider itself is open source and free to install.
- Users bring API keys, use provider billing, use local models, or route through compatible providers.
- There is no bundled seat model; the commercial customer relationship is mainly with model providers and any teams that standardize Aider internally.

## Who They Capture

- Terminal-first developers who want transparent control over files, context, costs, and commits.
- Open-source contributors who prefer BYOK or local models over subscription quota systems.
- Teams that can standardize conventions and test commands without buying a full agent platform.

## Who They Miss

- Developers who expect graphical code review, integrated issue management, previews, or cloud task delegation.
- Teams needing centralized governance, SSO, spend dashboards, or signed audit trails.
- Users who do not want to reason about model choice, token spend, context files, and Git hygiene.
