# Marketing

## Target Customers

- Individual developers and small teams who are productive in Git but frustrated by branch switching, stash management, and messy local changes.
- Teams using GitHub or similar hosted forges that want cleaner pull requests without replacing their remote platform.
- Developers curious about AI-assisted commit and branch workflows but not looking for a full AI coding environment.

## Positioning

GitButler positions itself as a new Git client for modern branch workflow. The pitch is practical: organize work into virtual branches, make better commits, and submit cleaner review units while keeping the existing Git ecosystem.

## Customer Model

GitButler has an open-source desktop client and hosted/account features around collaboration and product services. Pricing and entitlement details should be rechecked before sales comparisons because the product is still moving quickly.

## Captures

- Developers who feel Git is powerful but too awkward for parallel local work.
- Teams that want better stacked-branch hygiene before adopting a larger platform like Graphite.
- Users who prefer a native client with direct visual control over a browser-hosted forge workflow.

## Misses

- Organizations that require centralized policy, audit, compliance exports, and admin reporting.
- Teams that cannot install desktop apps or that standardize on web IDEs and remote workspaces.
- Users who need a new repository data model rather than a better Git client.

## Epoch Lessons

Epoch should position its history model as compatible with better local UX. GitButler captures the "my branch state is chaos" pain; Epoch should capture the "my history needs durable evidence and portable trust" pain.
