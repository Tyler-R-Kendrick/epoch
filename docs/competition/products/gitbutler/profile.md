# GitButler

GitButler is a desktop Git client that competes on branch ergonomics rather than repository hosting. Its core pitch is virtual branches: developers can work on multiple independent branch lanes in one working directory, split changes into stacked branches, and push reviewable units without constantly stashing or checking out.

## Competitive Relevance

- GitButler attacks the same pain Epoch cares about at the user-experience layer: making messy local history easier to understand, split, and share.
- Virtual branches, branch lanes, stack controls, commit-message generation, and change assignment turn the Git working tree into a visual planning surface.
- Because it works with existing Git hosting, it can improve daily developer workflow without asking a team to migrate its forge or storage model.
- AI features position the client as an assistant for commit hygiene and branch review preparation, not just a graphical shell over Git commands.

## Epoch Implications

- Epoch should expect users to compare any history UX against GitButler's immediate local affordances, not only against command-line DVCS tools.
- GitButler shows that "better history" can be sold as fewer context switches and cleaner review units before it is sold as a new data model.
- Epoch's deeper differentiator is verifiable, signed, portable history. The product should still borrow GitButler's strong lesson: users need simple ways to split intent into reviewable, named changes.

## Unknowns To Track

- GitButler is evolving quickly, so feature names and free/pro boundaries may change.
- The product is tied to a desktop app workflow; web-first, remote, and heavily regulated teams may need a different collaboration model.
