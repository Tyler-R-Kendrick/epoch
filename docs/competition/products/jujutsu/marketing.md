# Marketing

## Target Customers

- Developers who understand Git but want safer history editing.
- Teams using stacked changes, Gerrit-style workflows, or heavy rebasing.
- Tooling enthusiasts willing to adopt a new CLI.

## Positioning

Jujutsu presents itself as a Git-compatible VCS that is both simple and powerful. It emphasizes safety, powerful history manipulation, and a better model for conflicts and undo.

## Customer Model

Open source project with community adoption rather than a hosted SaaS model.

## Captures

- Advanced Git users frustrated by rebase, index, conflict, and recovery workflows.
- Teams that can standardize on `jj` or tolerate mixed Git/Jujutsu usage.

## Misses

- Users who need a hosted collaboration product, not a local VCS.
- Teams whose code review platform assumes branch-based Git workflows.
- Beginners who are already confused by Git and may not want another vocabulary.
