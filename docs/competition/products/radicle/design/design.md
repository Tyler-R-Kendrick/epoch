# Design

## Look And Feel

Radicle's public site uses a technical, hacker-oriented aesthetic: monospace-heavy typography, command snippets, compact sections, protocol vocabulary, and a strong "sovereign forge" identity. The product stack spans CLI, TUI, web, and desktop rather than one single polished web app.

## Open Design Assets

- Public website pages document the product story and include command-first onboarding.
- Product screenshots are referenced for Radicle Desktop and web/TUI surfaces, but the primary open design artifact is the product site and protocol documentation rather than a full public design system.

## Differentiators

- The design makes the ideological position visible immediately: sovereignty, peer-to-peer, cryptographic authorship, and data ownership.
- CLI-first onboarding fits technical early adopters and reinforces trust in local control.

## What Works

- The marketing and product vocabulary are coherent with the architecture.
- Protocol and product layers are presented together, which helps expert users trust the system.
- The local-first story is concrete: nodes, seeds, Git storage, and signed artifacts.

## UX Breakdowns

- The same ideological and protocol-heavy language can alienate teams that simply want easier collaboration.
- Peer-to-peer availability and seed-node concepts create operational questions earlier than centralized forge users expect.
- Git remains underneath, so Radicle inherits Git's file-level conflict and workflow complexity.
