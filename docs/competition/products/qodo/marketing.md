# Qodo Marketing

## Target Customer

Qodo targets teams that are adopting AI coding but are worried about review quality, merge risk, test coverage, duplicated logic, and noisy code-review bots. The buyer is often an engineering manager, maintainer, or platform team responsible for keeping code quality from degrading as AI-generated pull requests increase.

## Positioning

- Qodo is positioned as code quality for the AI era.
- The code-review pitch emphasizes multi-agent review, context-aware feedback, and rule enforcement.
- Marketing leans into measurable review quality, noise reduction, and trustworthy pull-request feedback.

## Customer Model

- Qodo offers free and paid plans with monthly credit allowances.
- Qodo Merge and review workflows depend on licensed users for feedback at scale.
- Enterprise buyers get custom licensing, governance, and deployment conversations.

## Who It Captures

- Teams that want automated PR review without replacing their existing Git workflow.
- Maintainers drowning in AI-generated pull requests.
- Organizations that want a quality layer independent from the code-generating agent.

## Who It Misses

- Developers who want an agent to make code changes rather than review them.
- Teams that prefer local, scriptable review commands over a hosted PR integration.
- Buyers that need final review evidence stored as signed history instead of PR comments.

## Epoch Opportunity

Qodo reinforces Epoch's thesis: AI-generated changes need review evidence. Epoch should make that evidence durable, signed, and tied to the exact accepted tree state.
