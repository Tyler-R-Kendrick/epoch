# Marketing

## Target Customers

- Engineering organizations and open source projects that need strict code review before integration.
- Platform teams willing to self-host and configure review infrastructure.
- Large multi-repository projects that value submit rules, replication, audit metadata, and custom plugin integrations.

## Positioning

Gerrit positions itself as code review for Git, with deep workflow control rather than a general-purpose all-in-one project management suite.

## Customer Model

- Open source software with community support and commercial vendors/consultants around hosting, support, and integration.
- Adoption is usually infrastructure-led: a platform or project governance team chooses Gerrit for a community or enterprise, then contributors follow that workflow.

## Captures

- Projects where branch protection is not enough and every change needs label-based review state.
- Teams that want review metadata stored in a Git-compatible backend and replicated as infrastructure.
- Organizations with custom presubmit, CI, and ownership rules.

## Misses

- Teams that want a consumer-simple forge with issues, projects, packages, and marketing pages out of the box.
- New contributors who expect pull requests and are confused by `refs/for`, patch sets, and vote labels.
- Organizations that prefer SaaS procurement over self-hosted review infrastructure.
