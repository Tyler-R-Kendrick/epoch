# Marketing

## Target Customers

- Postgres-backed product teams that need local, reactive, partial data sync.
- Developers building web, mobile, desktop, server-worker, or agent workflows that need live subsets of operational data.
- Teams that want local-first app behavior without replacing Postgres or routing writes through a new database product.
- Infrastructure-minded startups that value open source, benchmarks, and deployment flexibility.

## Positioning

Electric positions itself as Postgres Sync: a read-path sync engine for partial replication, data delivery, and fan-out. The message is that developers can keep Postgres and their existing write API while syncing just the data each local client or service needs.

## Customer Model

- Open-source core with public GitHub development.
- Cloud dashboard and hosted/service packaging around the sync engine.
- Adoption through docs, demos, integrations, benchmark material, and local-first developer education.
- Enterprise appeal through reliability, scalability, Postgres compatibility, and operational documentation.

## Captured Audiences

- Teams already standardized on Postgres.
- Developers who prefer SQL-shaped sync scope over CRDT-specific document modeling.
- Agent and worker builders who need local state slices without directly hammering the primary database.
- Organizations that want incremental sync infrastructure rather than a full application platform.

## Missed Or Under-Captured Audiences

- Teams needing built-in end-user collaboration, review, branch, and audit surfaces.
- Non-Postgres shops unless they are willing to introduce Postgres into the architecture.
- Users expecting Electric to own writes, conflict resolution, and domain permissions end to end.
- Buyers looking for a packaged source-control or artifact-history product.
