# Marketing

## Target Customers

- Web application teams with Postgres backends that want instant reads, optimistic writes, and realtime updates.
- SaaS teams building Linear-like, issue-tracker-like, support, planning, or dense operational products.
- Developers already convinced that network latency, cache invalidation, and frontend state plumbing are slowing product work.
- Teams that want open-source self-hosting but also need a managed or BYOC support path.

## Positioning

Zero positions itself as general-purpose sync for the web. It sells a specific outcome: queries and writes feel instant because the relevant data is local, while Postgres and application server code remain authoritative.

## Customer Model

- Open-source project for self-hosted adoption and trust.
- Managed cloud with visible monthly tiers for hobby and professional users.
- Bring-your-own-cloud plan for organizations that need data residency and limited vendor privileges.
- Community-led onboarding through docs, demos, Discord, and customer testimonials.

## Captured Audiences

- Frontend-heavy product teams that want to delete hand-written caching, loading, optimistic update, and realtime code.
- Postgres shops that do not want to replace their primary database.
- Startups whose competitive advantage depends on perceived app speed.
- Builders looking for the successor path from Replicache.

## Missed Or Under-Captured Audiences

- Teams that need Git-style branch, commit, review, and signed artifact history.
- Organizations that cannot adopt a young sync engine or product-specific query layer.
- Users outside web and React-oriented application stacks.
- Buyers looking for a complete collaboration product rather than infrastructure.
