# Marketing

## Target Customers

- Large engineering organizations with monorepo scale problems.
- Developers who like Git/Mercurial concepts but need easier stack, recovery, and navigation workflows.
- Teams that value local CLI speed and clear repository state.

## Positioning

Sapling positions itself as a source control system built at Meta for usability and massive scale, while remaining familiar to Git and Mercurial users.

## Customer Model

Open source CLI with public Git repository support. The strongest internal value proposition depends on Meta-scale server and filesystem infrastructure.

## Captures

- Power users and teams struggling with large histories, stacks, and Git mental models.
- Organizations willing to adopt a new SCM for scale and usability.

## Misses

- Teams that require a complete public hosted forge.
- Users who need the full Meta monorepo infrastructure outside Meta.
