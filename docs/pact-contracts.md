# Pact Contract Testing

Epoch uses **official** [Pact](https://docs.pact.io/) consumer-driven contracts
(`@pact-foundation/pact`) for HTTP service integration boundaries.

Agent guidance: [`.grok/skills/pact/SKILL.md`](../.grok/skills/pact/SKILL.md).

## Boundaries under contract

| Consumer | Provider | Interactions |
|---|---|---|
| `Epoch.Community.Core` | `Epoch.Community.API` | `GET /workflows`, `GET /repositories`, `POST .../issues`, `POST .../changes` |
| `Epoch.Core.GossipClient` (`HttpGossipPeer`) | `Epoch.Core.GossipHttp` | `POST /epoch/gossip` snapshot exchange |

## Commands

```bash
npm run test:pact            # consumers write ./pacts then providers verify
npm run test:pact:consumer   # generate contracts only
npm run test:pact:provider   # verify existing ./pacts against live providers
```

Consumer tests also run as part of `npm run test:unit:runtime` (Community contracts).
Full consumer+provider verification is the dedicated `test:pact` script.

## Layout

```text
pacts/                                 # durable generated contracts
test/pact/helpers.ts                   # PactV3 factory, Fetch→Node HTTP adapter
test/unit/community-contract.test.ts   # Community Core consumer
test/pact/consumer/gossip-http.consumer.test.ts
test/pact/provider/community-api.provider.test.ts
test/pact/provider/gossip-http.provider.test.ts
test/pact/run-pact-tests.ts
```

## Rules

1. Contracts are generated by **real client code** against Pact mocks.
2. Providers are verified with **real handler/server code**, not reimplemented doubles.
3. Private/federated ATProto in-process APIs without HTTP stay unit-tested; when they grow HTTP, add Pact.
4. Path-based gossip remains a unit concern; **HTTP gossip** is a Pact boundary.

## Optional Pact Broker

Set `PACT_BROKER_BASE_URL` (and token/username) in CI to publish:

```bash
npx pact-broker publish ./pacts \
  --consumer-app-version="$(git rev-parse HEAD)" \
  --broker-base-url="$PACT_BROKER_BASE_URL"
```

Local development does not require a broker.
